# Writey — Handoff

The single place to learn **what Writey is, what was decided and why, where it stands, and what's next**.

---

## 1. The idea (in the owner's words, condensed)

A digital notepad: laptop + pen tablet (later iPad + Apple Pencil). You write, solve problems, take notes, import PDFs and images and write on top of them. You pick pens, paper and backgrounds. That part is basic and table stakes.

On top of it sits an AI you **talk to**. The old way is screenshotting your work into another AI. The new way: while you're solving, you just **say** something, with no button press:

- "Writey, solve this" / "what's next?" / "continue" → it **writes the next step in handwriting on the page**, continuing your work.
- "Writey, how does this work?" / "I don't get this step" → a **chat box pops up on the side** and explains.

It "sees" your work because we own the canvas: it reads your strokes, the PDF text and an image of the region you're working on. No screen capture.

The owner wants **both** outputs (chat and handwriting). Writey picks one from what you said, and you can always override.

## 2. Who it's for

- Started as "just me" (the owner is the primary user, showcasing it on a laptop + Huion pen tablet).
- Then became **open source (MIT), multi-user, $0 hosting, bring-your-own AI keys**. This is the current direction, and the deployed app has Google login.
- Subjects: **math and physics**, any level (school, college, engineers, self-study).

## 8. Gotchas

- The URL is `<worker>.<account subdomain>.workers.dev`. The account subdomain was `anilreddy2569900` until 2026-10-25, when it became `writey` (API: delete, then create; there's no rename). Changing it again breaks the Helper's allowed origins (`apps/helper/writey_helper/config.py`) and Supabase's Site URL / redirect list. Cloudflare Workers Builds deploys every push to `main` (deploy command `cd apps/worker && npx wrangler deploy`, Supabase `VITE_*` values set as build variables).
- Free Supabase org allows only 2 active projects. The `roleplay` project was **paused** to make room. Don't unpause it without freeing a slot.
- Use `pnpm run deploy`, not `pnpm deploy` (that's a pnpm built-in). See AGENTS.md for the non-interactive deploy recipe.
- Worker free plan: ~10 ms CPU per request. Stream AI bodies through unparsed; never parse big bodies in the Worker.
- Worker secret `CREDENTIALS_KEY` encrypts every saved provider key. If it is lost or changed, users must re-enter their keys. Local dev uses a different key in `apps/worker/.dev.vars`.
- Biome must not format `pnpm-lock.yaml` (pnpm rewrites it), so it's excluded in `biome.json`. CI was red from 2026-10-24 until this fix because docs weren't Biome-formatted. Run `pnpm format` before pushing doc edits.
- Writey Helper: users install it with the setup file from Settings; devs run `uv run --directory apps/helper writey-helper`. Bump `API` in `writey_helper/__init__.py` (and `HELPER_API` in `apps/web/src/lib/helper.ts`) when Writey needs a newer Helper. A running dev Helper locks `.venv\Scripts\writey-helper.exe`, so use `uv run --no-sync pytest` while it runs. Its tokens live in `%APPDATA%\Writey\helper`. Windows consoles use cp1252, so keep the console output ASCII-safe (`main()` also sets `errors="replace"`).
- The e2e test user's password lives in `apps/web/.e2e.local` (gitignored, this machine only). Reset it via SQL if it's missing.
- InkScript prompts tell the model to double backslashes in JSON, but `repairJson` (packages/inkscript/src/script.ts) also fixes "\frac"-style slips, which would otherwise parse as a form feed plus "rac".
- Rebuild the handwriting glyphs with `pnpm --filter @writey/inkscript glyphs` (reads the `hersheytext` dev dependency). `glyphs.data.ts` is generated and excluded from Biome.
- Running `writey-helper` while one already runs: the same version prints "already running" and exits; an older one is stopped and replaced (Windows). Bump the version in `pyproject.toml` and `__init__.py` together.
- Voice needs Helper API 4 (`VOICE_API` in `apps/web/src/lib/helper.ts`); ChatGPT still needs only 2. Speech models live in `%APPDATA%\Writey\helper\models` and are shared by every Helper install on the machine.
- The VAD model and the ONNX runtime WebAssembly are served under `/vad/` by a Vite plugin (`apps/web/vite.config.ts`): from `node_modules` in dev (Vite refuses imports from `public/`), emitted as assets in the build. `ort-wasm-simd-threaded.wasm` is ~14 MB, under the 25 MiB Workers asset limit.
- The Claude desktop browser pane blocks microphones. To test voice there, replace `navigator.mediaDevices.getUserMedia` with a stream from an AudioContext and play Helper TTS into it.
- Python patches written with `open(..., 'w')` on Windows produce CRLF; `.gitattributes` normalizes on commit, but Biome may complain first.
